# 本棚

紙・電子・未所持を区別して蔵書を管理する、単一HTMLのPWA。
ビルド不要。`index.html` をそのまま GitHub Pages などに置けば動く。

## できること

- **バーコードで登録** — スマホのカメラで裏表紙の ISBN（978…）を読む。
  カメラの無い環境では USB バーコードリーダーの連続スキャンに対応。
- **探して登録** — タイトル・著者・ISBN で国会図書館サーチを引く。
  持っていない本も「未所持」として登録でき、買うべき巻として追われる。
- **まとめて入力** — 「オーバーロード 1-15」のように1行1作品で一括登録。
- **シリーズの抜け巻検出** — 巻数ストリップに未登録の穴が赤い破線で出る。
- **新刊を調べる** — 棚のシリーズごとに、所持最大巻より先の巻が出ていないか確認。
  見つかった巻は札とストリップに金色で残るので、あとで買うときも忘れない。
  完結にした作品は対象から外れる。調べてから2週間たつと棚の上でそっと促す。
- **外伝・スピンオフを探す** — シリーズ画面から、その作品の外伝を一覧できる。
  原作者が共通するものを「関連する作品」、同名の別作品を分けて出す。
- **持ちかた × 読みかた** — 所有（紙/電子/未所持）と体験（未読/読書中/読了/中断）を
  別の軸で持つ。「アニメで見た」も記録できる。
- **まとめて棚から出す** — 巻を選んで外す（シリーズ画面）、作品ごと外す（メニュー）。
  重なった巻はその場で1タップ。どの削除も直後に「元に戻す」で戻せる。

## データの置き場所と控え

**棚のデータは端末のブラウザの中にしか無い。** ブラウザのデータを消すと棚も消える。

- メニュー（下部バーの「…」）→「JSON で書き出す」で控えを取る。
  書き出しには本のほか、完結の印と並び順の設定も含まれる。
- 「JSON を読み込む」で別の端末に持っていける（同じ ISBN は重複しない）。
- **PC・スマホのデータを合わせる** — 同じ本のメモ・読書状況も反映する場合はこちらを使う。
  違う値を比較し、項目ごとにどちらを残すか選べる。クラウドへの自動同期は未設定。
- しばらく控えを取っていないと、棚の上に催促が出る。

### PC・スマホ間で手動同期する

1. 両方の端末でメニュー「…」→「PC・スマホのデータを合わせる」→「JSONで書き出す」で控えを取る。
2. JSONをもう片方へ渡す。対応端末では「JSONを共有する」から共有先を選べる。
   JSONの共有に非対応なら保存画面を開くので、保存したファイルを渡す。
3. 受信側で「受け取ったJSONと比較する」。既存の本はISBN・登録IDで照合する。
4. 違うメモ・読書状況・書誌・完結の印を選んで反映する。新規の本は選択して追加できる。
   片方にだけある本は残す。削除を反映する場合は「この端末にだけある本」で対象を明示的に選ぶ。
5. 反映結果のJSONを元の端末にも戻し、同じ比較を行う。

並び順・新刊確認記録は各端末の設定を残す。ISBN不明の同じ巻や重複IDは自動統合しない。
確認中に棚が変わった場合は上書きを止める。保存失敗時は元の棚に戻し、途中終了は次回起動で復旧する。
直前の反映前の控えは同期メニューから取り出せる。ただし端末内の控えなので、外部にもJSONを保存する。
旧版のJSONも比較できるが、両端末でメモ等を反映するには両方とも手動同期対応版を開く。

## 使っている外部サービス

| 用途 | サービス | 備考 |
|------|---------|------|
| 書誌検索 | 国会図書館サーチ (opensearch) | 巻数が構造化されており和書の網羅率が高い |
| 書誌の補完 | openBD | 国会図書館で引けなかった ISBN の保険 |
| 書影 | Amazon → Google Books | 「表紙なし」画像は寸法で見分けて次の候補へ |

Service Workerは書誌 API の応答をキャッシュしない（新刊検出が固定化するため）。
アプリ内には検索用の期限付きキャッシュがあり、新刊の再確認はこれを迂回する。
書影とフォントは Service Worker が貯め、機内モードでも棚が見える。

## 置き方

1. このリポジトリを GitHub Pages で公開する（`.nojekyll` 済み）。
2. スマホの Chrome で開き「ホーム画面に追加」すると全画面の PWA になる。
3. カメラは https（または localhost）でのみ使える。

## ファイル構成

- `index.html` — アプリ本体（CSS/JS すべて込み。設計判断はコード内コメントに記載）
- `sw.js` — Service Worker（ページはネットワーク優先、書影はキャッシュ優先）
- `manifest.json` / `icon-*.png` — PWA まわり
- `PLAN.md` — 精査で見つかった不具合と改善の計画表
- `PLAN-SPEED.md` — 高速化の現状分析と実施計画
- `HANDOVER.md` — 引継ぎ資料（設計思想・データモデル・JSとDOMの契約）
